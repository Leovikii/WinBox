## 启动白屏：当前实现与验收

用户确认白屏发生于前端 UI 出现前；仅统一 HTML 底色与 React 首帧主题不能覆盖原生窗口先显示的阶段。源码确认 Tauri 先创建配置窗口再执行项目 setup，原有窗口默认可见；主题/Mica 设置、前端资源加载及 React 提交都在之后。

当前主窗口 visible=false。后端完成代理恢复、窗口主题/材质及 setup 配置，且 React 提交后通过 frontend_ready 通知时，才放行首次显示。该通知不等待业务快照或网络请求，也不依赖隐藏 WebView 可能暂停的 requestAnimationFrame。它证明前端已提交，不声称原生合成器已完成首帧；用户已实机确认白屏修复。

StartupWindow 为单次显示门控：普通启动请求展示；最小化启动不请求展示；代理恢复失败与通知冷启动请求展示；初始化期间的托盘/单实例/权限提示显式 Show 请求延后到就绪。重复 frontend_ready（包括 StrictMode）不会重新展示或抢焦点；就绪后的显式 Show 保留恢复窗口和聚焦行为。后端配置和前端通知两种到达顺序均受测试覆盖。

后端 setup 完成后10秒仍未收到前端通知时，记录应用日志并释放门控，仅展示已请求可见的窗口，不把最小化自启变为弹窗。HTML 在 JS/CSS 失败时仍有加载与托盘退出提示；HTML 本身也加载失败时该提示不可保证，但托盘 Show/Quit 仍可用。未就绪时的原生关闭请求隐藏窗口，不依赖尚不可用的前端监听。迟到的就绪通知不重复抢焦点。10秒仅为失败兜底，不是正常启动等待时间。

保留上一轮首帧主题修复：HTML 解析缓存/系统主题，React 首次渲染沿用；提交后撤去临时底色以显示 Mica；后台快照刷新缓存。没有新增依赖、额外启动窗口或变更业务权限。
