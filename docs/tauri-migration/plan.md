# 后端迁移阶段与关闭门槛

2026-09-21：实现和 alpha.1 首次发布已完成。P0–P5 以下内容保留为实施范围与验收门槛，不是重新实施清单；尚缺证据的人工场景已统一收敛到 [validation.md](validation.md#待补人工验收2026-09-21)。前端准备见 [独立入口](../frontend-refactor/README.md)。

工作量不使用未经验证的工期承诺。以下阶段门槛优先于进度百分比；实际状态见 [tracker.md](tracker.md)。所有阶段遵循 [architecture.md](architecture.md) 的前端可优化边界。

## P0 — 基线、依赖和关键技术验证

任务：MIG-001–004。输入为当前 Wails 源码和可复现的基线构建。

- 记录 Go/Node/Wails/Rust/MSVC/WebView2 环境与 Windows AMD64/x64 目标；保留基线提交和产物摘要，不执行无必要的依赖升级。
- 盘点全部 Backend/runtime 调用、事件、默认值、数据布局、托盘及启动行为；采集脱敏数据 fixtures 和视觉基线。
- 检查官方插件/候选 crates 的准确版本、维护状态、许可证、支持平台；锁定最少依赖组合。
- 做边界原型：管理员 Tauri WebView、单实例、隐藏启动、最高权限延迟自启、动态内核路径、优雅退出/崩溃恢复、NSIS updater、旧版手动迁移说明。原型验证后删除无用脚手架。
- 明确 Windows 最低支持版本、x64 验证安排、ARM64 排除范围、NSIS 安装模式、数据路径与回退策略。

退出条件：关键能力有证据或明确阻断；NSIS updater、权限、数据目录和手动迁移说明已记录，不能以“之后研究”进入依赖这些决策的实现。常规选型自行决定；改变批准范围才提交用户确认。

## P1 — Tauri 外壳与前端接入

任务：MIG-005–006；依赖 P0。

- 建立 Tauri 2 工程，复用现有 Vite/Vue 与资产，不重建 UI。
- 完成窗口、Mica/主题、托盘、单实例、隐藏启动、关闭行为及清理入口骨架。
- 建立薄 API 层、类型化 DTO 与统一错误；直接更新 imports、composables 和事件管理。临时兼容桥必须有移除条件。
- 去除版本信息对 `wails.json` 的长期依赖，适配拖动区域，配置最小 Tauri permissions/CSP。
- 对尚未迁移的功能明确开发状态，不将 mock 结果当功能验收；发行产物不允许依赖假后端。

退出条件：现有界面可在 Tauri 运行，桌面行为与视觉通过；通信类型和订阅生命周期通过检查，未迁移功能清单明确。

## P2 — 存储、配置与订阅

任务：MIG-007–008；依赖 P1 和数据路径决策。

- 实现 `appLocalDataDir()` 路径、持久化、恢复、设置和订阅管理；旧便携数据不在程序内自动加载或导入。
- 迁移覆盖配置、IPv6/日志配置处理、内核配置校验及版本读取。
- 使用现有文件布局，避免无必要 schema 重写；保留可恢复备份。
- 完成应用日志与内核日志接口，保持内容与交互，删除重复前端请求/状态。

退出条件：正常、缺字段、损坏、中断、中文/空格路径等 fixtures 通过；写入失败不伪报成功；旧数据不丢失；配置语义与无关字段保留有检查。

## P3 — Windows 核心能力

任务：MIG-009–011；依赖 P2。

- 完成内核协调、模式切换、重启、进程退出、日志与流量、智能连接。
- 实现系统代理状态归属和恢复、权限失败处理、自启任务迁移、UWP。
- 所有入口共用状态来源；取消和退出收尾有边界；快速点击/托盘并发不得产生多内核或卡死状态。

退出条件：Windows 三种模式、网络故障、启动失败、内核崩溃、应用重启、自启与 UWP 实机验收通过。清理不会影响其他软件进程或代理。

## P4 — 更新、构建与发行演练

任务：MIG-012–014；依赖 P3 和 P0 的更新方案。

- 分别完成内核事务式更新和官方 Tauri updater 应用更新，保持镜像、预发布设置及进度交互。
- 删除自定义应用更新 helper、应用替换/回滚和 portable 应用更新链；旧便携用户按发行说明手动安装并自行处理旧数据。
- CI 使用锁定版本的官方 Tauri CLI/工具链，仅构建和发布 Windows x64 NSIS，并收集对应运行证据。
- 版本只有一个权威源；发布元数据和签名产物对应同一版本。密钥经 CI secrets 注入，更新签名与 Windows Authenticode 分开记录。
- PR 只验证构建，签名/发布使用适当受控流程；不沿用任何不合适的推送即发布行为。

退出条件：在测试发布源完成 NSIS 升级、拒绝错误签名/错误架构、下载中断、安装前退出清理和恢复演练；无密钥时相关任务标 blocked，不能假装完成。实作演练不等于获得正式发布授权。

## P5 — 全量验收与移除旧栈

任务：MIG-015–017；依赖 P4。

- 执行完整 validation 矩阵；同环境比较启动、空闲 CPU/内存、托盘后台负载、日志压力和退出清理，记录基线与候选数据。P0 确定可复现测量方法，不凭感觉声称更快。
- 同场景比较主题、缩放、Mica、布局和动画，以及全部操作路径。前端简化必须保持效果。
- 移除 Go/Wails、临时桥、旧配置及构建依赖；扫描源码、文档、忽略规则、CI，保留历史资料中必要的迁移说明。
- 更新项目 README、开发/发行/恢复说明；确保新环境按文档可构建；关闭阻断项并完成交接。MIG-042 是本次迁移的最终发行收尾，不再新增 portable/MSI/ARM64/Linux 产物。

退出条件：总体验收通过，无孤立旧调用和双版本源；Linux 能力未被误报；任务与证据齐全。删除旧栈在功能验证后执行，不能先删再寻找行为依据。

## 分阶段回退

- 开发回退：保持小而可审查的提交，每个阶段可独立回退；不以破坏用户未提交修改的 reset/clean 作为常规手段。
- 数据回退：使用迁移前备份与隔离测试目录；明确新版本写入后旧版是否可读，不能承诺无条件降级。
- 内核回退：保留旧二进制与有效配置，恢复后重新验证运行；系统代理也恢复到一致状态。
- 应用回退：先停止应用与内核，使用已验证的旧 NSIS 产物和对应数据备份；旧便携版本只按发行说明手动转换，不承诺安装版与旧便携二进制无条件降级。签名策略不为回退关闭。
- 删除旧构建链前保留基线 tag/提交和构建说明；不强制在本次文档任务创建 tag 或发布。

## P5.1 — 最终发行收尾（MIG-042）

这是当前重构计划的最后一个执行切片。方案已批准并完成代码/自动化实现；签名 Release 已核对通过，卸载/数据清理已由用户实测通过；其他安装器分支与跨版本更新仍不伪记为完成。

### 目标

- 只发布 Windows AMD64/x64 NSIS 安装包。
- 使用 `tauri-plugin-updater 2.11.0` 完成检查、签名验证、下载和安装。
- 保留现有更新界面及 `pre_release` 预更新设置，不新增独立更新 channel。
- 将用户数据固定在 `appLocalDataDir()`；不实现旧便携 `data/` 的自动导入，只提供发行说明中的人工备份/复制步骤。
- 安装前复用统一退出流程，确保 sing-box 退出、流量停止和代理恢复。

### 执行顺序

1. 已用最终 NSIS/updater 决策替代 portable-only 发布草案；旧方案仅保留历史证据。
2. 已接入并锁定官方 updater，更新 Tauri 配置和 Rust 更新封装；删除自定义应用更新链，保留 sing-box 核心更新。
3. 已收口数据路径、安装升级/卸载保留规则和人工迁移说明；没有增加首次启动迁移流程、目录扫描或数据合并逻辑。
   - NSIS 固定默认 `%ProgramFiles%\WinBox\`，隐藏路径/组件选择页，仅保留必要 UAC 确认并在安装完成后启动应用。
   - 以构建后文件清单校验安装目录只含主程序、Tauri/Windows 必需 loader/资源和卸载文件；配置、订阅、核心、日志、代理恢复状态全部位于 `appLocalDataDir()`。
   - 保持现有 JSON 布局，仅按功能需要创建 `config/`、`profiles/`、`core/` 和日志文件；更新/写入/核心替换的临时文件只在成功或恢复完成后清理，恢复未完成时保留最小恢复材料，不保留无功能用途的长期 `updates/` 或 `backups/`。
4. 已接入 updater 安装前清理 hook，复用统一退出清理；不在安装调用时持有生命周期锁，避免 hook 死锁。
5. 已将 GitHub Actions 改为 x64 NSIS：PR 只构建验证，合并 `main` 后使用 secrets 签名并发布 NSIS `*-setup.exe`、同名 `.sig` 和 `latest.json`；Tauri v2 Windows updater 不额外生成 `.nsis.zip`。
6. 已更新 README、contracts、decisions、tracker、validation；`.gitignore`、版本号、x64 目标和产物命名已完成静态复核。
7. Rust/前端、unsigned/signed NSIS、签名匹配和发布元数据模拟均已通过；main Release 资产已核对，卸载/数据清理已实测通过；首次安装其余分支、升级、错误签名、真实退出清理与预更新 UI 仍待 Windows x64 验收。

- private key 和 password 只配置到 GitHub Actions secrets。
- Release workflow 具备 `contents: write` 权限。
- 安装包 UAC 行为和人工数据说明完成 Windows x64 验收。

MIG-042 只有在最终 NSIS 产物、官方 updater 签名资产、人工数据说明、更新前清理、GitHub Action/Release 和应用内跨版本更新均有证据后才能标记 `done`。在此之前，`review`、`todo` 或未执行项如实保留。
